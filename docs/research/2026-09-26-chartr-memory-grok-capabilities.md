# Grok memory and capture interfaces for Chartr

Date: 2026-09-26. Research for **Verify Grok memory and capture interfaces**. This supplements the earlier provider report; Grok's external capabilities are no longer wholly unverified. It does not select rollout or capture policy.

## Result and evidence limits

Official Grok Build has documented MCP tool access and plausible automatic-capture seams: lifecycle hooks, native session identity, persisted sessions, and transcript export. Chartr's existing Grok integration provides identity and display metadata, not a complete capture pipeline. Explicit memory support is therefore technically supported by the public interfaces, but compatibility with a selected released binary still needs verification.

Inspected Chartr `32f5977db187034c4b920a58152a0996b234bc06`, its exact Herdr pin, and current first-party Grok source at `f0e3be1100ef5252488e3be8bb0e91cf68d8c305`. Sources below were retrieved read-only. No provider was launched, private transcript inspected, or credentials accessed. Neither `grok` nor `grok-build` was found by PowerShell command discovery in this environment; that does not establish availability on the target macOS/Linux machines. No runtime tests were performed.

## Exact product and local integration

The intended product is xAI/SpaceXAI **Grok Build**, installed as `grok`, whose official source is `xai-org/grok-build`. It is distinct from calling a Grok model through the inference API and from unrelated third-party CLIs. Official documentation offers macOS/Linux installation; the source README identifies macOS/Linux as supported build hosts and explains that the built artifact is `xai-grok-pager`, distributed as `grok`. [Product documentation](https://docs.x.ai/build/overview), [official source README](https://github.com/xai-org/grok-build/blob/f0e3be1100ef5252488e3be8bb0e91cf68d8c305/README.md)

Chartr's catalog accepts `grok` and `grok-build`, with `TerminalOnly` transport. This describes Chartr messaging transport, not lack of MCP support. Its history code honors `GROK_HOME` (default `~/.grok`), can locate a matching `sessions/<workspace>/<session>/updates.jsonl`, and reads titles from identity-checked `summary.json`. The history reader deliberately returns an empty transcript for Grok. Finding a log or displaying its title is not evidence that Chartr parses its contents. [Catalog](../../crates/chartr-agent/src/lib.rs), [paths and reader](../../crates/chartr-conversations/src/transcripts.rs), [title reader](../../crates/chartr-conversations/src/transcripts/titles.rs)

Chartr pins Herdr `0.8.2-chartr.5a2dee700eee`, revision `5a2dee700eeeea68267a4d16777307632f77172f`, protocol 22. Its Grok installer registers only `SessionStart` in a dedicated `hooks/herdr.json`; the shell hook reports `GROK_SESSION_ID` (falling back to payload fields) through `pane.report_agent_session`. It does not forward transcript content or turn completion. Preserve its owned files and install any capture hook separately. Herdr's detection manifest references Grok Build 0.2.101 and derives coarse activity from terminal titles/progress/UI. That historical evidence is not a minimum version for memory features. [Chartr pin](../../crates/chartr-herdr/src/lib.rs), [Herdr installer](https://github.com/herdrdev/herdr/blob/5a2dee700eeeea68267a4d16777307632f77172f/src/integration/targets.rs), [session hook](https://github.com/herdrdev/herdr/blob/5a2dee700eeeea68267a4d16777307632f77172f/src/integration/assets/grok/herdr-agent-state.sh), [detection manifest](https://github.com/herdrdev/herdr/blob/5a2dee700eeeea68267a4d16777307632f77172f/src/detect/manifests/grok.toml)

## Documented explicit-memory seam

Grok supports local STDIO and remote HTTP MCP servers. Native configuration is `[mcp_servers.<name>]` in `~/.grok/config.toml`, using `command`/`args`/`env` or `url`/`headers`. `grok mcp add --scope project` writes `.grok/config.toml`; project entries override user entries of the same name. Compatibility sources include Claude/Cursor MCP files at lower priority. `grok mcp list` and `doctor` support JSON output; `grok inspect` reveals configuration origins. `/mcps` can refresh configuration, though this research does not guarantee live reload in every released version. These interfaces can expose Chartr's explicit read/write tools without replacing the terminal UI. [Official MCP documentation](https://docs.x.ai/build/features/mcp-servers)

## Capture and evidence seams

| Surface | Established evidence | Limit for Chartr |
| --- | --- | --- |
| Hooks | Personal/project JSON hooks can run commands or POST to HTTP endpoints. Documented events include `SessionStart`, `Stop`, `StopFailure`, subagent and compaction events. Project hooks/MCP require trust. Inputs include session ID, working directory and workspace root. [Hooks](https://docs.x.ai/build/features/hooks) | A stop notification is not an exactly-once durable capture queue or proof that all background work ended. |
| Current source envelope | `HookEventEnvelope` has optional `transcriptPath` and `promptId`. Current source additionally defines `StopCancelled`; stop payloads can carry last assistant text and background task information. Camel-case fields are authoritative; selected snake-case aliases are emitted. [Pinned source](https://github.com/xai-org/grok-build/blob/f0e3be1100ef5252488e3be8bb0e91cf68d8c305/crates/codegen/xai-grok-hooks/src/event.rs) | Optional fields are not guaranteed present. A source snapshot is not proof the installed release has these fields/events. |
| Session identity and evidence | Conversations persist under `~/.grok/sessions`; docs describe prompts, responses, tool calls and snapshots. Resume/fork are supported; `grok export <id> [file]` produces Markdown. Rewind truncates the conversation; compaction changes context. [Sessions](https://docs.x.ai/build/features/sessions) | Export completeness, stable record IDs, subagent inclusion, flushing and retained pre-compaction evidence remain untested. Do not treat Markdown as a stable structured event schema. |
| Headless/ACP | Headless output supports newline-delimited streaming JSON. ACP uses `session/update` for assistant chunks and `session/prompt` completion metadata. [Headless/ACP](https://docs.x.ai/build/cli/headless-scripting) | This documents running an agent under that transport, not passive subscription to an independently running Chartr terminal. |

Documentation is not completely uniform: the CLI/session pages say `--session-id` creates a new session and `--resume` resumes; the headless page describes `--session-id` as create-or-resume. The short hooks page calls `PreToolUse` the only blocking event, whereas current source classifies `Stop` as a gate. Use explicit resume and verify actual hook behavior against the selected release rather than generalizing from the short guide. [CLI reference](https://docs.x.ai/build/cli/reference), [headless reference](https://docs.x.ai/build/cli/headless-scripting), [hooks guide](https://docs.x.ai/build/features/hooks), [event traits](https://github.com/xai-org/grok-build/blob/f0e3be1100ef5252488e3be8bb0e91cf68d8c305/crates/codegen/xai-grok-hooks/src/event.rs)

## Smallest prerequisite validation

No additional product identification or private account information is needed to continue design decisions. Before calling Grok support verified, use disposable state on each target OS with an explicitly recorded official binary version:

1. Configure one harmless local MCP fixture with read/write round-trip tools. Verify discovery, tool invocation and persistence in a new session and an explicitly resumed session, alongside Herdr's existing integration. Record the configuration origin and trust behavior without retaining credentials.
2. Install a separate passive recording hook for start, stop, failure and cancellation when supported. Run synthetic prompts covering completion, interruption, resume and fork. Compare emitted session/prompt IDs with Herdr identity and check that continuing stop hooks do not masquerade as final completion.
3. Export only those synthetic sessions and inspect their local logs. Establish whether a hook's optional transcript path points to the same evidence, whether the final content is readable when the hook fires, and which tool/subagent records survive export, compaction and rewind. Test duplicate notification and restart reconciliation before selecting cursors or deduplication keys.

These checks require access to a supported host and an authorized Grok installation/authentication or supported local model. Public documentation is sufficient to establish candidate interfaces, but not a minimum released version, durable capture guarantees, or a tested compatibility matrix. Keep explicit MCP access, identity, evidence readability and automatic-capture readiness as separate capabilities. Grok remains in the user-selected provider set; this research does not substitute OpenCode or decide whether automatic extraction must launch for all three providers together.
